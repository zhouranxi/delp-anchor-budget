## 1. 诊断结论：预注册内部矛盾，不是实现缺陷

§2 把噪声模型锁死为「概率 ρ 每 phase 独立抽取，T=10」。在此模型下，一个 run 完全没有错标的概率是 `(1−ρ)^T`：

| ρ | P(零错标) | 该 ρ 的 noisy run 数 | 期望零错标数 |
|---|---|---|---|
| 0.1 | 0.9¹⁰ = 34.87% | 80 | 27.9 |
| 0.2 | 0.8¹⁰ = 10.74% | 80 | 8.6 |
| 0.4 | 0.6¹⁰ = 0.60% | 80 | 0.5 |

v1 实测 26 个零错标，**全部落在 ρ∈{0.1, 0.2}**（ρ=0.1: 20，ρ=0.2: 6），ρ=0.4 为 0。按 mode 拆分：`fwd|0.1` 16/40、`full|0.1` 4/40、`fwd|0.2` 2/40、`full|0.2` 4/40；两个 mode 的标签抽样使用不同的隔离 RNG 种子（`MODES.index(mode)*7919`），故组间计数不同属抽样波动。全部 280 个 run 的 `phase_labels` 长度均 = 10；`λ=1000.0`、`nh=256`、`ell/avg/bwt` 全部非空；G1/G2/G4 全部 PASS，其中 clean 臂与 S4 λ 修正版 ρ=0 的 40 个配对最大偏差 **0.005 点**。

即：噪声注入机制确实生效，§7.3「ρ>0 的臂必须 `n_mislabeled > 0`」这条**逐 run** 判据与 §2 的**逐 phase 伯努利**机制在数学上不可能同时满足。这是预注册起草时的条款冲突，不是脚本漏注入。

## 2. 决策：不放宽判据，按 §7 排查后重跑

可以选择「把 G3 事后改成 arm 层级并保留 v1」，但那属于**看到数据后放宽硬门槛**，正是本项目 S4 修订说明反复警戒的做法，故不采用。采取 §7 原文规定的路径：

1. **v1 数据作废，不用于任何主推断**；文件保留，仅作为 as-treated 敏感性对照公开。
2. **G3 判据本身一字不改**：`ρ>0` 的每个 run 必须 `n_mislabeled > 0` 且 `phase_labels` 长度 = T。
3. 修改的是**噪声抽样规则**（实现层），使判据可以被字面满足。新规则在数据前写死为 `--noise-rule guaranteed`，完整定义见 §3。
4. 用新规则**重跑全 280 runs**（不是只补跑 26 个），得到自洽的 v2 数据集；§5 全部判读以 **v2** 为准。只补跑零错标 run 会按「处理强度」条件化选样，引入选择偏差，故不采用。
5. v1 与 v2 并列报告，若两者结论一致，作为稳健性证据；若不一致，以 v2 为准并额外披露。

## 3. 新噪声规则（guaranteed）的精确定义

在训练开始前一次性预抽 T=10 个 phase 标签（RNG 调用顺序与 v1 完全相同，因此 `bernoulli` 分支可逐位复现 v1）：

```
labels = [draw_label(p, rho, rng, T) for p in range(T)]
if rule == "guaranteed" and all(labels[p] == p for p in range(T)):
    p = rng.randrange(T)
    labels[p] = (p + 1 + rng.randrange(T - 1)) % T
```

`draw_label` 及 `rng = random.Random(...)` 的种子公式均不变；`clean` 分支仍不调用标签 RNG、不调用任何额外 torch RNG，故 **G2 clean 对齐不受影响**。脚本新增 `--noise-rule {bernoulli,guaranteed}`，默认 `bernoulli`（v1 可复现），v2 显式传 `guaranteed`；每个 run 的 JSON 增记 `noise_rule` 字段。

**estimand 的变化（必须披露）**：v1 的 estimand 是「按 ρ 独立错标」的无条件效应；v2 是「按 ρ 独立错标、**条件于至少一次错标实际发生**」的效应。低 ρ 下实际处理强度略升（ρ=0.1 的期望错标数由 1.0 升至约 1.35）。因此 v2 是**更保守（更容易检出效应）**的检验：若 v2 仍为零效应，结论比 v1 更强。收数报告须列出各 ρ 的实际平均错标数。

## 5. 时序诚实性披露

`analyze_r1.py` 在同一次运行中同时打印 §7 门槛与 §5 的 H1 / 存活判据，因此起草本修订时**已看到 v1 的 H1 数值**（四个 cell 均 `|mean|<0.5`、`p>0.15`）。披露如下：

- 修订的**唯一依据**是 G3 的机制级冲突（§1 的数学期望在看到任何指标数值前即可算出）；判据数值、阈值、臂、指标**没有因看到 H1 而被调松或调紧**。
- 选择的是**成本更高、对原结论更不利**的路径（全量重跑 + 更保守的 estimand），而非保留 v1 的省力路径。
- 本文件落盘时间 18:04:51，**早于 v2 任何数据**；v2 的启动命令、日志、JSON 均随包公开。
