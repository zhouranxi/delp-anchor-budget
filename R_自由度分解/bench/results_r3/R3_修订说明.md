# R3 修订说明：cnn_delp.make_anchor_cnn 的 GPU 设备修复（运行时补丁）

**落盘时间**：2026-11-12 00:37:30 +0800（**先于任何 R3 网格数据**；pilot 在 GPU 上触发该 bug 后、修复落地前，无任何 R3 数据落盘成功）
**触发**：pilot（`lam=0, base, mnist, s0`）在第一个锚构造处崩溃：`make_anchor_cnn` 的 `out, _ = model(xs_grad, ctx1)` 抛 `Input type (torch.FloatTensor) and weight type (torch.cuda.FloatTensor)`。

## 1. 诊断：E5 的潜伏设备 bug，被 R3 的 GPU 选择首次暴露

- `cnn_delp.make_anchor_cnn`（L189–219）接收训练侧的 `xs`（CPU 张量，来自 `load_data`）直接喂给已 `.to(DEV)` 的模型；
- E5 的 conv 网格**全部跑在 CPU**（`run_e5_arch2.sh:8`：`CUDA_VISIBLE_DEVICES=''`）→ CPU/CPU 恰好匹配，bug 从未触发；
- R3 按预注册 §1 跑 GPU 2/3 → 首次暴露。**E5 历史数据不受此 bug 影响**（CPU 上语义正确），无需任何重跑。

同链条检查：`e5_arms.run_one` 主循环里 `xb.to(DEV)` 已正确；`usage_dead_mask`/`_trunk`（gsprobe 分支）也各自 `.to(DEV)`——唯一漏的是 `make_anchor_cnn` 的 `xs_grad` 与 `ctxr`。

## 2. 处置：运行时 monkey-patch，E5 文件零改动

预注册 §2 写死「不动 `e5_arms.py`/`cnn_delp.py` 任何一行」。为守住该条款，修复以 **`r3_lamsweep.py` 模块级补丁**实现：

```python
_orig_make_anchor_cnn = _cnn.make_anchor_cnn
def _make_anchor_cnn_devfix(model, xs, task_id, ntask):
    xs = xs.to(E5.DEV)          # CPU batch -> model device (the only change)
    return _orig_make_anchor_cnn(model, xs, task_id, ntask)
_cnn.make_anchor_cnn = _make_anchor_cnn_devfix
```

- 语义：仅把输入张量搬到模型设备，**锚构造逻辑零改动**（Fisher、usage 掩码、dom 统计逐字原样）；
- 作用域：只在 R3 进程内生效；`e5_arms.py`/`cnn_delp.py` 文件**未修改**（MD5 不变：`1f058113…`/`71c2b628…`）；
- 旁证：E5 的 `_bd_make_anchor_dispatch` 走 `import cnn_delp as _cnn` 后按属性调用 → 补丁天然被调度路径命中；
- CPU 兼容：`.to(DEV)` 在 DEV=cpu 时是 no-op，若将来在 CPU 复跑 R3 亦不受影响。

**不改判据**：λ 轴、臂、网格、M1–M4 判读、Holm 家族、门槛全部不变。此修订只修「能不能在 GPU 上跑起来」，不触碰任何统计条款。
