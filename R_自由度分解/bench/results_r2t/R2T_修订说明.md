# R2T 修订说明：§7 G5 检查器的字段口径修正

**落盘时间**：2026-11-11 23:02:00 +0800（修正后重跑判读之前）
**触发**：R2T 全网格 30 runs（22:57:55 / 22:58:07 收完，rc=0）跑 §7 门槛时 **G5 FAIL**（`n_bad=30`，即全部 run 被判字段缺失）。其余五个门槛 PASS。分析器在门槛阶段即 ABORT（exit 2），**未输出任何判读结果**。

## 1. 诊断：数据完好，检查器字段口径错误

- `analyze_r2t.py` 首版在 G5 中用 `METRICS=("ell","avg","bwt")` 逐键检查 `r.get(m)`；
- 但 R2T 按预注册 §1「与 E9 逐字一致」继承 E9 的 JSON schema，其 avg 指标存储键为 **`final_avg`**（R2 的 MLP JSON 才用 `avg`）；
- 实测：30/30 run 的 `final_avg` 全部非空、`ell/bwt` 非空、`acc_matrix` 均为 10 行下三角。**数据零缺陷**；G5 的 30 个 FAIL 全部是检查器用错键名造成的假阳性。

与 R2 第二次修订（G2 证据来源）同类：**检查器实现口径错误**，非训练实现缺陷、非预注册条款冲突、非数据问题。

## 2. 处置：修检查器，不改判据、不改数据、不改预注册

- `R2T_预注册.md` 一字未改；G5 的判据内容（三指标非空 + acc 矩阵形状完整）**不变**，仅修正其读取键（`avg` → 存储键 `final_avg`），新增模块级 `get()` 访问器并同步修正 `paired_delta`/`extras` 的同一口径。
- 训练数据 `r2t_grid.part{0,1}.json` 一个字节未动（MD5 `1d72de3f…` / `9686c6cd…`）。
- 判据家族、三层判读 T1/T2/T3、Holm 家族、方向一致性、探索性比较——全部不变。
- 修正后的 G5 语义与预注册 §7.5 的**意图**（指标齐全、矩阵完整）一致且更正确地实现了它。
