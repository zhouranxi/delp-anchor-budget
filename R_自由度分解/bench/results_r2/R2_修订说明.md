# R2 修订说明：§7 G4 历史对齐参照的设备口径修正

**落盘时间**：2026-11-11 20:01:17 +0800（**先于任何 R2 全网格数据**）
**触发**：pilot（16 runs，GPU 2，`/tmp/r2_pilot.json`）的 §7 门槛检查中 **G4 FAIL**：`n_pairs=6, max_abs_diff=1.652 > 0.5`。其余门槛 G1/G2/G3/G5 全部 PASS（G6 因 pilot 只有 16 runs 而非 240，属预期）。
**处置依据**：`R2_预注册.md` §7 原文「未达则数据作废、排查后重跑」、§8「任何偏离必须写入独立修订说明，不修改本文件」。**`R2_预注册.md` 一字未改。**

## 1. 诊断：不是实现漂移，是参照数据的设备口径不匹配

`E6E7_预注册.md:52,88` 明写 E6/E7 用 **CPU venv**（「CPU venv，8 分片并行」）；E5 网格同理。而 R2 按用户指定跑在 **GPU 2/3**（共享卡，利用率 0%，显存上限 8%）。`kWTA` 是离散 top-k 操作，CPU/GPU 的微小浮点差异会改变幸存者集合，并在 T=20 的连续任务流上累积放大。

在服务器上用**同一个 `e5_arms.py`**、同一种子、同一 T，只切换 `CUDA_VISIBLE_DEVICES`，各重跑 `base` / `renorm` 两臂（mnist, T=20, seed=0）：

| 指标 | 历史 E5 (`e5_t20_*.json`) | CPU 重跑 `e5_arms.py` | GPU 重跑 `e5_arms.py` | **R2 pilot** |
|---|---|---|---|---|
| base `ell` | 51.76 | 52.08 | **52.19** | **52.19** |
| base `avg` | 39.82 | 39.92 | **39.72** | **39.72** |
| base `bwt` | −12.57 | −12.80 | **−13.13** | **−13.13** |
| renorm `ell` | 62.51 | 62.76 | **60.86** | **60.86** |
| renorm `avg` | 48.39 | 48.88 | **48.05** | **48.05** |
| renorm `bwt` | −14.86 | −14.62 | **−13.49** | **−13.49** |

两条结论：

1. **GPU 重跑的 `e5_arms.py` 与 R2 pilot 的 `base`/`renorm` 逐位完全一致**（2 臂 × 3 指标，0 差异）。R2 的 uniform 训练循环与 E5/E6 基线**零实现漂移**——G4 意图检验的东西完全达标。
2. CPU 重跑与历史 E5 数据的偏差均 ≤0.5 点（最大 0.49），而 CPU↔GPU 同脚本偏差最大达 **1.90 点**（renorm `ell` 62.76 vs 60.86）。即历史数据是 CPU 口径、R2 是 GPU 口径，两者本就不满足 0.5 点可比性。

**旁证**：本地与服务器的 4 个共享模块 `e5_arms.py` / `branch_delp.py` / `exp6_baselines.py` / `exp4_branch_protection.py` 的 MD5 **逐位一致**，排除 plumbing 版本差异。

## 2. 处置：不放宽阈值，只隔离设备变量

**阈值、判据、网格、指标、统计口径、Holm 家族、条件触发条款，全部不变。** 唯一改动是 §7 G4 的**参照数据生成方式**：

| 项 | 原 §7 G4 | 修订后 |
|---|---|---|
| 参照 | 历史 CPU 数据 `results_e6/e6_s*.json`（T=10 base）、`results_e5/e5_t20_*.json`（T=20 base/renorm） | **同设备（GPU 2/3）重跑 `e5_arms.py` 的 `base`/`renorm` 双臂**，覆盖 `2 ds × 2 T × 10 seeds × 2 arms = 80 runs`，独立存盘 `r2_e5gpu_ref.part{0,1}.json` |
| 比对 | R2 uniform 臂 vs 历史，逐 `(ds, seed)` | R2 uniform 臂 vs GPU 参照，逐 `(arm, ds, T, seed)`；**阈值仍 ≤0.5 点** |
| 历史 CPU 数据 | 直接参与判定 | 降级为**旁证链**：CPU 重跑 vs 历史 ≤0.5 → R2(GPU) vs GPU 重跑 ≤0.5 → 历史在链条内但跨设备不直接比较 |

这不是放宽判据：原 G4 的目的是「检测 R2 实现是否忠实复现 E5/E6 基线」，新口径把设备变量**控制住**，检验力更强；且新增 80 runs 的独立参照，比原来复用旧数据更严格。

**pilot 数据按 §7 作废**：`r2_pilot.json`（SHA-256 `76895a3a2dceeb44f6b47147c1dec6bb6ef8e73516734ed7df4ad7edef6ec0ba`）仅作为本诊断的证据留档，**不进入任何主推断**。全网格按修订后的 G4 口径全新运行 240 runs。

## 3. R2 统计推断不受影响

R2 的全部配对（候选臂 vs `base` / `renorm`）都在**同一设备、同一脚本、同一 seed**内进行，本身就与 E5/E6 历史数据无关。历史数据只用于 §7 的实现对齐校验，不参与任何 Δ 计算。因此本次修订不改变任何效应量或 p 值的计算方式。

## 4. 数学一致性复核（R1 教训）

R1 的 G3 FAIL 源于「per-phase 伯努利抽样」与「逐 run 必须至少一次错标」在 `(1−ρ)^T` 下冲突。本次修订**不引入任何随机抽样式条款**：G1/G2/G3/G5/G6 均为确定性不变量，修订后的 G4 是**确定性同设备对齐**（同一脚本同一 seed 同一设备应逐位相同）。落盘前已用 pilot 的 2 臂实跑验证该对齐为 0 差异。
